Mill exposes a remote MCP server at your installation's `/mcp` URL. A compatible client connects only with OAuth, which you approve in Mill. Personal and team API keys are for REST access. Mill does not run the client or require an LLM key for task management.

## Connect a client with OAuth

Open **Account Settings → MCP Guide** and choose your client: Codex, Claude Code, Cursor, VS Code, or Other clients. Copy the configuration shown for your installation. The guide uses the configured public API origin plus `/mcp`; remote connections need HTTPS. Local HTTP OAuth works automatically when `MILL_API_URL` is an exact loopback origin.

Start the connection in your client. It opens Mill's consent page. Sign in, check the application name, then choose Read-only, Write, or Administrator access. Mill offers only levels allowed by your current role. Client-requested scopes do not choose your grant. A dynamically registered client name is unverified; an HTTPS metadata document describes a client but does not verify who started the request. Approve only a connection you started.

Choose Administrator on Mill's consent screen if you need administrative access and your Mill role permits it. Mill currently has no admin-only MCP tools, so this grant does not add tools to the catalog. Ordinary task and board tools follow the connection owner's current role and board access.

New connections use your current role and board access. A Viewer can grant Read-only access; Members can also grant Write, and Administrators can also grant Administrator. Choose **Approve** to finish the connection or **Deny** to refuse it. **Back to the client** also denies the request and returns through its callback. If Mill asks you to confirm your identity again, complete that step before approving. Any role change revokes your existing OAuth connections, including a promotion, so reconnect and choose access again.

## Review and revoke access

Open **Account Settings → MCP Connections** to see connected clients, their read-only, read/write, or administrative permission, expiry and last use. New connections show only the selected permission level and follow your current board access. Older restricted connections also show their retained board limits. Use **Revoke connection** when a client no longer needs access. Revocation takes effect on the next request. Deleting a board removes it from restricted grants; if it was the connection's last approved board, Mill revokes the connection.

OAuth access tokens work only with `/mcp`, expire after 30 days, and have no refresh token. Clients may advertise refresh-token support in their metadata, but Mill issues authorization-code access tokens only. Reconnect from the client when one expires. Older board-restricted connections cannot create boards or list the team directory. MCP tools available to the client depend on its approved scopes and your current role and board access; its writes use the same task versions and retry behavior as REST. When private S3 storage is configured, attachment tools create signed image/PDF uploads, verify completion, list files, issue download URLs and delete attachments within the approved task scope. File bytes move directly through the signed URL. There are no Agent, Kanban, custom-status or checklist tools.

If a connection fails, check the exact `/mcp` URL, HTTPS or loopback setting, chosen access level, and current role. A `401` usually means the credential expired or was revoked; a `403` means the action exceeds the approved access. See [client troubleshooting](/troubleshooting#an-mcp-client-cannot-connect) and [individual tool reference](https://www.mill.fyi/mcp-reference/overview).
