# October 5 Towbar and Mill UI pattern review

This review compares the current local source in both checkouts. Towbar is the read-only reference. Mill uses locally adapted Apache-2.0 components; it does not require a sibling checkout to build. The broader findings below are source comparisons, not claims that every Towbar flow was reproduced in a browser.

## Changes implemented

- Sessions follows Towbar's resource table: Session, Session ID, Last active, Expires, Status and Actions. Short IDs use shared code typography with the complete ID available in a tooltip. Last active and expiry use relative time with the absolute time below, respecting the user's time zone. The current browser has an accent Current chip and disabled Revoke action; other sessions have success Active chips. Mobile rows stack all details without page overflow.
- Revoke opens a confirmation dialog and retains pending/error recovery there. A failed response is reconciled against the authoritative list; an already-absent session resolves successfully. Successful revocations stay hidden through later stale list responses. Live devices were not revoked during visual inspection; mutation evidence uses isolated fixtures.
- The OSS-safe ResourceTable recipe is shared by Sessions and task activity. Its row-header column is explicit, so a future Task ID column need not become the row header. Activity uses TableCellStack/TableCellDescription and renders an empty state instead of an empty table header.
- Initial query loading uses the shared invisible status announcement for Sessions, passkeys, board tasks, API keys, people, invitations and activity. Existing data, cursor loading, retry focus and permissions remain owned by their existing hooks.
- Profile explains Gravatar and provides the same edit link pattern as Towbar. Email/Password and Two-factor widgets omit repeated heading icons. Authenticator setup uses shared CodeBlock/CopyButton, with text-sm introductory and action copy.

The implemented changes and executed browser/build evidence are recorded in [v1 verification](b1-verification.md#october-5-sessions-and-shared-ui-patterns).

## Intentional differences to preserve

Mill already shares the underlying button, input, select, dialog, chip, avatar, widget, empty-state, table and typography patterns. It does not need a wholesale control rewrite.

Mill's passkey-first reauthentication, recovery fallback, independent task saves/conflict recovery, cursor loading, revoked-response guards and idempotent creation are deliberate behavior. Towbar's ActionButton currently closes its confirmation before an asynchronous request; copying it directly would regress Mill's required pending/recovery controls inside the initiating dialog; success and error feedback now uses global toasts.

MCP Guide configuration reflects Mill's OAuth-only transport. Towbar's manual-key configuration must not be copied as if Mill accepted it. Team-owned keys, email-change delivery and workspace audit settings need product/server capabilities, not placeholder UI. Dedicated task pages, three board cards per desktop row, restrained widget headings, stable notification/breadcrumb controls and outgoing mobile drawer contents are accepted user decisions.
