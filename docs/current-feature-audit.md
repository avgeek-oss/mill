## Feature and boundary map

| Boundary                             | Current behavior and regression coverage                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reduced task model and migration     | Shared contracts, REST, and MCP expose six fixed statuses and no task checklist or comment-edit operation. `tests/domain.test.ts`, `tests/fixed-status.test.ts`, `tests/security-review.test.ts`, and `tests/status-migration.test.ts` cover rejected old fields/routes and preserved former subtasks as independent tasks. `tests/assignment-migration.test.ts` and the native packaged upgrade verify migration 010 retires nonempty checklist data privately, removes the active field, preserves task/discussion/notification data, and permits Agent-only attribution. |
| Agent assignment and grants          | `validateTaskAgent` checks actor access when a binding changes and checks any selected human assignee; no human assignee is required. Unrelated task edits retain a valid binding. Personal Agents belong to their creator; team Agents use selected grants or all-members access with a pinned active creator grant. `tests/agents.test.ts`, `tests/agents-concurrency.test.ts`, `tests/agents-access-policy-migration.test.ts`, and `tests/external-agents.test.ts` exercise creation, revocation, race ordering, and retained work.                                      |
| REST keys and MCP OAuth              | Personal REST keys inherit the human owner's current role across accessible boards and have no Agent/scope/board selectors. MCP OAuth selects an eligible existing Agent with approved scopes and optional board restrictions. `tests/external-personal-keys.test.ts`, `tests/external-oauth.test.ts`, `tests/external.test.ts`, and the native upgrade/restore SDK calls cover issuance, PKCE, permission changes, expiry, and revocation.                                                                                                                                 |
| Collection and direct-ID permissions | `requireRole`, board/task lookups, locked writes, and MCP tool filtering enforce board restrictions and human-only administration. `tests/domain-detail.test.ts`, `tests/domain.test.ts`, `tests/external.test.ts`, and `tests/security-review.test.ts` include negative collection and ID paths. OAuth returns 403 at the REST credential boundary; a signed-in person or personal REST key gets 404 from removed comment PATCH.                                                                                                                                           |
| Conflicts, retries, and deletion     | Board/task versions reject stale writes. Workspace locks, authority revalidation, and SQL triggers serialize access changes with mutations. Encrypted retry responses become terminal when referenced work is deleted or Agent access changes. `tests/task-history.test.ts`, `tests/retry-deletion.test.ts`, `tests/permanent-deletion.test.ts`, `tests/deletion-concurrency.test.ts`, and `tests/agents-concurrency.test.ts` cover the durable and race paths.                                                                                                             |
| Complete bounded lists               | Board, task, comment, activity, notification, Agent, credential, invitation, and member responses have bounded paging. A found 1,000-person member ceiling was fixed: REST `/api/auth/members` and MCP `list_members` now return `hasMore` and an opaque revision-bound `nextCursor`. `tests/member-directory-pagination.test.ts` traverses 1,006 active people through REST and actual MCP calls and rejects stale continuation with `409 member_list_changed`.                                                                                                            |
| Authentication and failures          | `tests/auth.test.ts`, `tests/http.test.ts`, `tests/config.test.ts`, and `tests/security-review.test.ts` cover setup, invitations, sessions, recovery, passkeys, authenticator fallback, current role, origins, rate limits, and bounded errors. The native runner additionally checked fresh setup and database failure/recovery.                                                                                                                                                                                                                                           |
