# Towbar foundation review

This records the controlled first UI foundation pass for the private Mill B1 draft. Foundation acceptance is limited to this checkpoint; it does not establish overall UI approval or release readiness. The earlier B1 screenshots and functional verification do not establish acceptance of the Towbar visual composition.

The source authority is the public Apache-2.0 Towbar checkout at `../towbar`, specifically `packages/web-design-system/src` and the public application compositions named below. No HeroUI Pro package, paid icon pack, private design-system package, or licensed private component was used. HeroUI, Hugeicons free icons, React Aria Components, Inter, and Geist Mono are public dependencies. Their attribution is recorded in `packages/web-design-system/NOTICE.md` and the root notices.

The shell is applied to every authenticated route. The board page uses the shared heading, secondary search and filter controls, Widget columns, and the actual HeroUI Table composition. The public React Aria RouterProvider connects Table and Link navigation to Mill's existing client navigation. Normal clicks and Enter retain the board's search, filters, and view; modifier/new-tab navigation and direct reload use the canonical `/boards/:boardId/tasks/:taskId` route. Long titles are bounded with TooltipText so desktop metadata remains visible; narrow table overflow is contained.

Board filters have explicit responsive slots. On phones, Search occupies a full-width row, Filters and Clear filters share a reserved action row, and expanded fields form a consistent two-column grid. Collapsed phone filters hide both select and label slots. A reserved clear-action slot prevents adding a reset action from moving the board. Filtered emptiness offers accurate copy and Clear filters in both views; archived/deleted collections and genuinely empty active boards have distinct recovery actions.

The independent narrow review confirmed:

- Desktop toolbar bottom stayed at 306px before and after filtered-empty recovery appeared: zero movement.
- Collapsed phone fields all measured 0×0; Filters stayed left-aligned at x=16px. Expanded controls formed six 173px fields in three paired rows, without document overflow.
- Normal task-link click followed by modal close, and Enter followed by browser Back, preserved the `nextstep` search, one-result list, and identical shell instance. Canonical routes still support native modifier/new-tab links and direct reload.
- The empty state describes unmatched filters and offers Clear filters; clearing restores existing tasks in both views.

Targeted TypeScript, ESLint, Prettier, and production build checks pass. The existing browser journeys retain their strict assertions and now include filter-preserving links plus both-view empty-state and stable-toolbar regressions. The complete combined browser run remains a separate integration check.

The production build succeeds. Its shared initial JavaScript chunk currently triggers Vite's 500kB advisory; the threshold has not been raised. This remains a performance follow-up, separate from visual acceptance.

## Remaining composition work held for pass two

Shared controls and the authenticated shell are available everywhere, but the following application compositions have not been migrated as part of this checkpoint:

- Setup, sign-in, invitation, recovery, and consent layouts; identity credential composition and password reveal.
- Board settings and destructive confirmations: responsive details/status grids, immutable prefix detail, color labels, and action hierarchy.
- Task detail's editor tabs, checklist/subtask rows, comments, activity, and draft warning composition.
- People list, Profile and notification preference Widgets, and account security's action-specific authenticator/passkey/password/session Widgets.
- Agent credential/MCP Widgets and documentation links; Inbox, audit, export/import, and dedicated import feedback composition.
- Shared loading skeletons and final 404/500 page composition.

Legacy application CSS retained for these pages is layout scaffolding; custom Mill palette tokens and global primitive, typography, SVG, and strong-element overrides were removed. Their replacement composition is a separate authorized review pass. API behavior, security boundaries, version handling, history pagination, and existing functional assertions remain in place.

Two concrete follow-ups are recorded for that pass: the task property grid in `task-dialog.tsx` needs zero-minimum-width containment for long selections and label inputs on phones; security reauthentication in `settings.tsx` needs a retryable passkey challenge, supported method selection after cancellation, form/Enter submission, and explicit loading/error states before rendering empty passkey/session lists. These are known review findings, not implied completed work.
