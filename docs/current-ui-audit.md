## Initial-load performance

The initial production entry measured **854.28 kB minified / 262.22 kB gzip** before the date picker split. A source-map diagnosis found calendar/date modules in the initial chunk because the design-system barrel re-exported `DatePickerField`; moving it to a task-only subpath reduced the entry to **688.12 kB / 210.88 kB gzip**, a 51.34 kB gzip (19.6%) reduction. The final `index-Cm2Sx23K.js` build measures **690.46 kB / 211.52 kB gzip**; its CSS is **484.14 kB / 49.72 kB gzip** (`tmp/final-review/verify-final-presentation.log`). Vite's 500 kB minified-entry advisory remains because the authenticated shell and interactive primitives are still on the critical path; no warning threshold was raised or vendor bundle split merely to change the report.

The controlled cold-load case used fresh cache-disabled Chromium desktop contexts at 1.6 Mbps down, 750 kbps up, and 150 ms latency. The uncompressed self-hosted server made sign-in usable by **7,002 ms** and board heading plus **New task** by **8,518 ms**; it transferred 690,067 B of entry JavaScript and 484,284 B of CSS (`tmp/final-review/cold-load-pre-divider.log`). After static-only gzip compression, the final `index-Cm2Sx23K.js` browser run made sign-in usable by **2,480 ms** and the board by **2,988 ms**; it transferred **209,821 B** of entry JavaScript, **49,597 B** of CSS, and **54,288 B** of board route JavaScript (`tmp/final-review/browser-final-cm2.log`). These are controlled local observations, not release-wide latency guarantees. Static smoke separately checks exact identity hashes, gzip decoding, MIME, CSP, cache and `Vary` headers; API and MCP responses remain outside static compression.
