# v1 verification

## October 7 shared authentication, account and team settings

Authentication, account settings and team settings now consume the published design-system compositions and standard copy. Passkeys is the account navigation label and `/settings/passkeys` is the canonical route; `/settings/two-factor` remains a compatibility alias. Profile, preferences, email/password, sessions, API keys, team name, members, invitations and invitation password setup use the shared patterns. Branding, permissions, direct invitation links and operator recovery guidance remain truthful Mill adapters.

Passkeys are the only second factor. Authenticator setup, verification, legacy recovery-code verification and their runtime dependency are removed. Genuine passkey recovery codes are issued at first enrollment and can be replaced only after fresh passkey proof. Recovery sign-in cannot create API keys, approve OAuth grants or change security settings without new passkey verification. The UI preserves the original password, API-key and OAuth drafts through cancellation, failed verification and retry. Cancellation aborts pending passkey options and the browser ceremony; server verification and committed mutations keep dismissal locked.
