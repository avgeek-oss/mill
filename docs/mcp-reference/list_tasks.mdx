Search and filter tasks in one board. Combine q, status, `assigneeId`, priority and sort. Without a status filter, done and wont_do tasks are hidden after 24 hours in that status. Set status explicitly to include older tasks in that status. Tasks are sorted by priority from urgent through none by default; status sort follows backlog, todo, in_progress, in_review, done, wont_do. Maximum 100 results per page, with total matching tasks and the current revision. Use either cursor continuation or a positive page number. Cursor cannot be combined with page or revision. Page requests clamp to the last available page; send the returned revision on subsequent page requests to reject changed lists.

## Access and behavior

A Read-only, Write or Administrator OAuth grant can call this tool within the user’s current team role. Tools are listed and callable only when the current grant and role permit them.

Priority is the default: urgent, high, medium, low, none. Without an explicit status filter, done and wont_do tasks disappear from lists after 24 hours in that status but retain direct access. q searches title, description, acceptance criteria and identifier. `assigneeId`:unassigned finds tasks without an assignee.

## Arguments

| Argument     | Required | Type or meaning                                                                                              |
| ------------ | -------- | ------------------------------------------------------------------------------------------------------------ |
| `boardId`    | Yes      | Board UUID, not its task prefix.                                                                             |
| `q`          | No       | string                                                                                                       |
| `status`     | No       | backlog, todo, in_progress, in_review, done, wont_do                                                         |
| `assigneeId` | No       | Active member UUID; null clears an assignment on mutation, unassigned filters unassigned tasks when listing. |
| `priority`   | No       | none, low, medium, high, urgent                                                                              |
| `sort`       | No       | createdAt, updatedAt, dueDate, priority, status, title                                                       |
| `limit`      | No       | integer                                                                                                      |
| `cursor`     | No       | Opaque nextCursor from the preceding response with identical filters.                                        |
| `page`       | No       | integer                                                                                                      |
| `revision`   | No       | Revision returned by the task list; send with numbered pages to reject concurrent list changes.              |

## Example call

The client initializes the MCP connection before sending this JSON-RPC call. Example records are fictional.

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "list_tasks",
    "arguments": {
      "boardId": "11111111-1111-4111-8111-111111111111",
      "sort": "priority",
      "page": 1,
      "limit": 25
    }
  }
}
```
