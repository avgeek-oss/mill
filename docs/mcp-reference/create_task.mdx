Create a task with optional Markdown description and acceptance criteria, type task or bug, a fixed status, assignee, priority, start date and due date. Type defaults to task and status to todo. Reuse `idempotencyKey` on retries.

## Workflow

```mermaid
flowchart LR
  step0["Resolve board and member UUIDs"] --> step1
  step1["Set fields and criteria"] --> step2
  step2["Create once with a retry key"]
```

## Access and behavior

Write or Administrator OAuth consent and a member/administrator team role are required. Tools are listed and callable only when the current grant and role permit them.

Creation requires title and defaults type to task, status to todo, priority to none, assignee and dates to null, and Markdown fields to empty. Active human assignees only. Mentions and assignments respect in-app notification preferences.

## Arguments

| Argument             | Required | Type or meaning                                                                                              |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| `boardId`            | Yes      | Board UUID, not its task prefix.                                                                             |
| `type`               | No       | task, bug                                                                                                    |
| `title`              | Yes      | string                                                                                                       |
| `description`        | No       | string                                                                                                       |
| `acceptanceCriteria` | No       | Independent Markdown acceptance criteria, at most 100,000 characters.                                        |
| `assigneeId`         | No       | Active member UUID; null clears an assignment on mutation, unassigned filters unassigned tasks when listing. |
| `priority`           | No       | none, low, medium, high, urgent                                                                              |
| `status`             | No       | backlog, todo, in_progress, in_review, done, wont_do                                                         |
| `startDate`          | No       | Optional calendar date YYYY-MM-DD; null clears it.                                                           |
| `dueDate`            | No       | Optional calendar date YYYY-MM-DD; null clears it.                                                           |
| `idempotencyKey`     | No       | One logical mutation key, reused unchanged on retries. MCP forwards it as the REST Idempotency-Key header.   |

## Example call

The client initializes the MCP connection before sending this JSON-RPC call. Example records are fictional.

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "create_task",
    "arguments": {
      "boardId": "11111111-1111-4111-8111-111111111111",
      "title": "Verify database restore",
      "description": "Restore a recent backup into an isolated database.",
      "acceptanceCriteria": "- Confirm task and comment counts match\n- Record the result",
      "type": "task",
      "priority": "high",
      "status": "todo",
      "assigneeId": "66666666-6666-4666-8666-666666666666",
      "startDate": "2027-01-18",
      "dueDate": "2027-01-20",
      "idempotencyKey": "restore-check-create-001"
    }
  }
}
```
