---
title: "update_task"
description: "Update a task with Mill MCP."
icon: "plug"
---

Edit task fields, including separate Markdown description and acceptance criteria, type task or bug, or its fixed status using the current version. A stale version returns a conflict.

## Workflow

```mermaid
flowchart LR
  step0["Read current version"] --> step1
  step1["Send changed fields"] --> step2
  step2["Refresh on conflict"]
```

## Access and behavior

Write or Administrator OAuth consent and a member/administrator team role are required. Tools are listed and callable only when the current grant and role permit them.

Fields save atomically. Pass null to clear `assigneeId`, `startDate` or `dueDate`. Actual status changes reset `statusChangedAt`; unrelated edits preserve it. A stale version returns 409 without applying the edit.

## Arguments

| Argument             | Required | Type or meaning                                                                                              |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| `taskId`             | Yes      | Task UUID, not its human identifier such as ENG-1.                                                           |
| `version`            | Yes      | Latest row version; stale mutations return HTTP 409.                                                         |
| `type`               | No       | task, bug                                                                                                    |
| `title`              | No       | string                                                                                                       |
| `description`        | No       | string                                                                                                       |
| `acceptanceCriteria` | No       | Independent Markdown acceptance criteria, at most 100,000 characters.                                        |
| `assigneeId`         | No       | Active member UUID; null clears an assignment on mutation, unassigned filters unassigned tasks when listing. |
| `priority`           | No       | none, low, medium, high, urgent                                                                              |
| `status`             | No       | backlog, todo, in_progress, in_review, done, wont_do                                                         |
| `startDate`          | No       | Optional calendar date YYYY-MM-DD; null clears it.                                                           |
| `dueDate`            | No       | Optional calendar date YYYY-MM-DD; null clears it.                                                           |
| `idempotencyKey`     | No       | One logical mutation key, reused unchanged on retries. MCP forwards it as the REST Idempotency-Key header.   |

## Example call

The client initializes the MCP connection before sending this JSON-RPC call. Example records are fictional.

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "update_task",
    "arguments": {
      "taskId": "22222222-2222-4222-8222-222222222222",
      "version": 1,
      "status": "in_review",
      "acceptanceCriteria": "- Restore completed\n- Counts match",
      "idempotencyKey": "restore-check-edit-001"
    }
  }
}
```

## Example result

Mill returns this object in `structuredContent` and normally a JSON text content block (large responses may shorten the text block). A tool failure sets `isError`; never treat an error as a completed mutation.
